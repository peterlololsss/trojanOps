# Decisions

Newest last. Reopening one needs the whole team; record the outcome as a new entry.

| # | Date | Decision | Why |
|---|---|---|---|
| 1 | 2026-11-14 | The product is the platform (integration, distribution, document permissions, governance). Agents are content on it. | The pitch is AI for every club, not one tool. |
| 2 | 2026-11-14 | Platform first on a mock runtime; real agents (WP-13, WP-14) last. No RAG code before then. | The platform demo can't depend on model behaviour or retrieval quality. |
| 3 | 2026-11-14 | The model sits behind `LLMProvider`; the provider is chosen at WP-13. | Lets the team pick a model late and switch to Trojan AI Gateway without code changes. |
| 4 | 2026-11-14 | Permissions use org-qualified grants enforced by Postgres RLS, capped by the agent's max tier. | Role-only checks leaked across clubs; the database, not the prompt, must enforce access. |
| 5 | 2026-11-14 | Audience (who uses an agent) and max tier (what it reads) are separate; a public agent's max tier is always Public. | Clubs can open agents to all students without exposing internal documents. |
| 6 | 2026-11-14 | Three distribution directions: USG → clubs, club → members, club → all students. Students see theirs on `/me/agents` and `/directory`. | Matches how clubs actually serve members and recruits. |
| 7 | 2026-11-14 | Public-agent runs are billed to the publishing club, need an installation limit, and count toward a per-student daily cap. | Outside students must not exhaust a club's quota. |
| 8 | 2026-11-14 | The gateway is a server module, not Next.js middleware. | It needs DB transactions and the runtime's actual usage. |
| 9 | 2026-11-14 | The funding pre-check is a demo agent; its rule pack uses demo values. | The selling point is the platform, not one rulebook. |
| 10 | 2026-11-14 | USC look: Cardinal and Gold, Source Sans 3 and Caslon titles, no USC marks, a "not endorsed by USC" footer. | USC brand and student-organization rules. |
| 11 | 2026-11-14 | Work is split into four streams with path ownership and stubs merged by H3. | Four agents in parallel without editing the same files. |
| 12 | 2026-11-14 | The role, RLS policies, `read_grants` trigger and `agent_runs_meta` view ship in WP-0, not WP-1. WP-1 proves them with the §10 tests. | Every stream can run `pnpm db:reset` and query as `trojanops_app` from H2. |
| 13 | 2026-11-14 | `EffectiveAgent` carries `status` (`enabled`, `disabled`, `retired`). | Gateway step 1 must refuse disabled installations and retired templates without a second lookup. |
| 14 | 2026-11-14 | DB integration tests connect as `trojanops_app` and skip with a notice when the database is unreachable. Sync points run them with Docker up. | `pnpm check` stays usable without Docker; RLS is never tested as the owner. |
| 15 | 2026-11-14 | Agent reads pass their max tier into `withActor`; the documents RLS policy checks it alongside grants and sources. | The same role can grant Officers and USG internal documents. The database must enforce the tier ceiling independently so access agrees with the permission preview. |
| 16 | 2026-11-14 | The document library (`/org/[orgId]/documents`) uses the actor's memberships in the viewed org (`orgId`), recomputed per request with `grantsFor`, not the active org. It never widens beyond positions held in that org. Upload still requires the active org (`app.manage_org`). | A student in several clubs can browse each club's library without switching; upload stays tied to the president's active org, as the `documents_insert` policy checks. |
| 17 | 2026-11-14 | `/` is a demo sign-in page (DEMO_MODE): a Sign-in ID and one shared demo password, checked in the browser only, then the frozen `POST /api/session/persona`. `/?account=N` prefills account N. A signed-in visit to `/` redirects to the role's landing page (USG admin → `/usg/integrations`, president → club home, other members → `/me/agents`, no club → `/directory`). `/` renders without the masthead and side nav, and the masthead lists personas only once someone is signed in. | The demo opens on a familiar sign-in instead of a list of names. The password adds no security: the trust boundary stays DEMO_MODE and `choosePersona`, as for the masthead switcher. |
| 18 | 2026-11-15 | Demo Economy costs 1 credit and Standard 3 credits; 1 credit is $0.01. Presidents enter dollars and see credits beside them. | Students see the cost before sending, while budget holders retain the existing micro-USD ledger. |
| 19 | 2026-11-15 | An optional per-run `modelClass` is checked against template, USG policy and the club override before a hold or runtime call. A null installation override lets members choose. | Model choice cannot widen distribution or bypass the priced quota hold. Frozen contracts and schema stay unchanged. |
| 20 | 2026-11-15 | Chat history is component memory only, cleared on navigation, persona change or New conversation; earlier messages are never sent to the runtime. Usage exposes only the current user's run metadata. | I15 remains enforceable without a conversation store or a new history API. Memory across navigation remains optional follow-up work. |
| 21 | 2026-11-15 | Knowledge chunks, index progress and word-overlap scores are deterministic demo UI derived from readable document text and `clock.now()`. Runs never use this demo index. | Knowledge management can be demonstrated without introducing retrieval, embeddings or model calls before WP-13/WP-14. |
| 22 | 2026-11-15 | Retrieval tests are president-only and reuse the permission preview's access cells. Upload requires a server-side access review, then the existing upload API recomputes and stores permissions through the DB trigger. | Previewing a hypothetical grant set never writes `read_grants` or bypasses RLS. |
| 23 | 2026-11-15 | Chat follows the user's Dify-style request: user messages right, AI answers left with an explicit label, transcript scrolling inside a bounded window and composer below it. | The two speakers remain easy to distinguish throughout a conversation. |
| 24 | 2026-11-15 | `/directory` is the org directory, not an agent list. USG and students outside a club browse clubs; a member acting in a club browses its departments. Club and department dashboards follow the EngageSC club page (header, About · Events · Members · Officers tabs, recent updates, upcoming events). A club's public agents are on its Agents tab. Departments, events and updates are demo content in `src/lib/directory/content.ts`, joined to real people, memberships, quotas and the published `usg-funding` cap. Supersedes 6 on where students find public agents. | USG oversees clubs and presidents run departments; both read a club the way students already do on EngageSC. Departments need no schema change for the demo. |
| 25 | 2026-11-15 | The `usg-funding` rule pack and the USG rulebook document use USG's published Funding Department Guidelines (current as of 2026-10-21), cited by section. D6's v2 ($10,000 cap) is a demo amendment. Supersedes 9. | The proposal's rule was "real rules, constructed records": a treasurer or reviewer recognises real clauses, and the examples show the rejection a treasurer would otherwise learn about too late. |
| 26 | 2026-11-15 | USG's funding rules are the USG rulebook document, read with the system prompt; rule packs leave the product UI and no template attaches one. USG admins publish new document versions; D6 is v2 of the guidelines. The rule-pack tables and route stay unused. Supersedes the rule-pack part of 25. | For an admin the rules are one document; a second rule object duplicated it and added a term nobody knew. |
| 27 | 2026-11-15 | `/me/agents` is one workspace: a rail of every agent the student can use, grouped by source (each of their clubs, USG, then other clubs' public agents under "All students"), beside the chat and an always-visible Run details panel. Rail items show name, purpose, topic tags and version, never the access reason. Topic tags are display content keyed by template slug. Opening an agent no longer leaves My agents. Adds to 24: public agents are also on My agents. | Students use agents from several sources in one place; access reasons were noise on the list, and the run page moved them into a club scope mid-task. |
| 28 | 2026-11-15 | The judge demo's organizer-handoff club is named HackSC, a real USC organization, as an exception to I13. Its people, meeting notes, handoff, finance worksheet and figures are fictional, and it is additive: Startup, Archery and Dance stay. Answers and AI summaries in the demo are mock output labeled "Demo". | The presenters asked for HackSC by name: judges recognise a hackathon club, so the first-time-organizer handoff reads as a real problem. |
| 29 | 2026-11-15 | Template versions store the specific demo models they offer (`model_ids`, `default_model_id`); `model_classes` and `default_model_class` are derived from them on publish. Club policy, the installation override, quota holds and prices stay class-based. A run may name `modelId`, checked against the template's models the club allows; the run and usage record that id. The USG template pages become a card list and a builder (always-editable form, live chat preview, publish bar). Revisits 19. | USG admins choose models the way members see them in chat; classes still govern spend, so clamps and budgets are unchanged. |
